# Contact Management Prototype Scope

## Introduction
This document defines the scope for the initial prototype of the Contact Management feature within the CRM. The aim is to develop a minimal viable product (MVP) that demonstrates the core functionalities of managing contacts.

## 1. Core Functionalities

The prototype will include the following essential features:

*   **Add New Contact:**
    *   **Description:** Allows a user to create a new contact record in the system.
    *   **Process:**
        1.  User navigates to a "Create New Contact" form or clicks an "Add Contact" button.
        2.  User inputs data into the specified contact fields (see section 2 below).
        3.  User submits the form.
        4.  The system validates the input (e.g., basic email format if feasible).
        5.  A new contact record is created with a unique `ContactID` and `CreatedAt` timestamp.
        6.  The user is redirected to the contact list or the newly created contact's detail view, with a success message.

*   **View Contact List:**
    *   **Description:** Displays all contacts in a summarized, list format.
    *   **Process:**
        1.  User navigates to the "Contacts" section.
        2.  The system retrieves all contact records.
        3.  Contacts are displayed in a table or list, showing key information such as `FirstName`, `LastName`, `Email`, and `Company`.
        4.  Each item in the list should be clickable to navigate to the "View Contact Details" page for that contact.
        5.  Basic pagination will be implemented if the number of contacts is large (e.g., 10-20 contacts per page).

*   **View Contact Details:**
    *   **Description:** Displays all stored information for a single, selected contact.
    *   **Process:**
        1.  User clicks on a contact from the "View Contact List" or after creating/editing a contact.
        2.  The system retrieves and displays all fields associated with the selected `ContactID`.
        3.  The view should clearly present all contact fields (see section 2).
        4.  Options to "Edit Contact" and "Delete Contact" should be available on this view.

*   **Edit Contact:**
    *   **Description:** Allows a user to modify the information of an existing contact.
    *   **Process:**
        1.  User navigates to the "View Contact Details" page for the contact they wish to edit.
        2.  User clicks an "Edit Contact" button.
        3.  The system displays a form pre-filled with the contact's current information.
        4.  User modifies the desired fields.
        5.  User submits the form.
        6.  The system validates the input.
        7.  The contact record is updated, and the `UpdatedAt` timestamp is refreshed.
        8.  The user is redirected to the updated "View Contact Details" page with a success message.

*   **Delete Contact:**
    *   **Description:** Allows a user to remove a contact record from the system.
    *   **Process:**
        1.  User navigates to the "View Contact Details" page for the contact they wish to delete.
        2.  User clicks a "Delete Contact" button.
        3.  The system prompts the user for confirmation (e.g., "Are you sure you want to delete this contact?").
        4.  If the user confirms, the contact record is permanently removed from the system.
        5.  The user is redirected to the "View Contact List" with a success message.

## 2. Contact Fields

The following basic data fields will be included for each contact record in this prototype:

*   **`ContactID`**
    *   **Description:** A unique identifier for each contact.
    *   **Type:** UUID or auto-incrementing integer.
    *   **Behavior:** Auto-generated by the system upon contact creation. Not editable by the user. Primary key for the contact entity.

*   **`FirstName`**
    *   **Description:** The first name of the contact.
    *   **Type:** Text.
    *   **Validation:** Required field.

*   **`LastName`**
    *   **Description:** The last name of the contact.
    *   **Type:** Text.
    *   **Validation:** Required field.

*   **`Email`**
    *   **Description:** The primary email address of the contact.
    *   **Type:** Text.
    *   **Validation:** Required field. Basic email format validation (e.g., contains "@" and a domain) should be attempted if feasible within the prototype scope. Should be unique across contacts.

*   **`Phone`**
    *   **Description:** The primary phone number of the contact.
    *   **Type:** Text.
    *   **Validation:** Optional field.

*   **`Company`**
    *   **Description:** The name of the company the contact is associated with.
    *   **Type:** Text.
    *   **Validation:** Optional field.

*   **`CreatedAt`**
    *   **Description:** Timestamp indicating when the contact record was created.
    *   **Type:** Timestamp/DateTime.
    *   **Behavior:** Auto-recorded by the system upon contact creation. Not editable by the user.

*   **`UpdatedAt`**
    *   **Description:** Timestamp indicating the last time the contact record was modified.
    *   **Type:** Timestamp/DateTime.
    *   **Behavior:** Auto-recorded by the system whenever the contact details are successfully edited. Not editable by the user.

This scope is intended to guide the development of a functional prototype. Features and fields beyond this definition are considered out of scope for this initial version but may be considered for future iterations.
